# PetLog

PetLog is a full-stack pet health tracker. It lets owners keep a shared health record for each pet — vaccinations, vet visits, medications, weight, and grooming — set due-date reminders, get AI-assisted guidance on symptoms, and share a read-only profile with anyone (a sitter, a co-owner, a new vet) via a link, no login required.

## Features

- **Pet profiles** — name, species, breed, date of birth, weight, and photo, one profile per pet.
- **Health records** — a timestamped log per pet across six categories: vaccination, vet visit, medication, weight, grooming, other.
- **Reminders** — due-date tasks per pet (e.g. "Next heartworm dose"), markable as done.
- **AI symptom checker** — describe symptoms in plain language and get likely causes, an urgency level (`can_wait` / `within_48h` / `go_now`), and home-care notes, generated by Claude and scoped to the pet's species/breed/age.
- **Public share links** — each pet gets a unique token (`/share/:token`) that exposes a read-only profile with no authentication.
- **Auth** — email/password and Google sign-in via Firebase; the API verifies Firebase ID tokens on every protected request.

## Tech Stack

| | |
|---|---|
| **Frontend** | React 19, TypeScript, Vite, React Router v7, axios, Firebase client SDK |
| **Backend** | Node.js 24 (native TypeScript, no build step), Express 5, Mongoose 9 / MongoDB |
| **Auth** | Firebase Authentication (client sign-in) + Firebase Admin SDK (server-side token verification) |
| **AI** | Anthropic API (`claude-haiku-4-5`) for the symptom checker |
| **Validation** | Zod (server) |
| **Styling** | Plain CSS with Material 3 design tokens — no UI component library |

## Getting Started

### Prerequisites

- Node.js 24+ (the server uses native TypeScript type stripping — no `tsc`/`ts-node` needed to run it)
- A MongoDB instance (local or [Atlas](https://www.mongodb.com/atlas))
- A [Firebase](https://console.firebase.google.com) project with Email/Password and Google sign-in enabled
- An [Anthropic API key](https://console.anthropic.com) for the symptom checker

### 1. Clone and install

```bash
git clone <repo-url>
cd PetLog
cd server && npm install
cd ../client && npm install
```

### 2. Configure environment variables

**`server/.env`**

```env
PORT=5000
MONGO_URI=mongodb+srv://<user>:<pass>@cluster.mongodb.net/petlog
FIREBASE_PROJECT_ID=
FIREBASE_CLIENT_EMAIL=
FIREBASE_PRIVATE_KEY="-----BEGIN PRIVATE KEY-----\n...\n-----END PRIVATE KEY-----\n"
NODE_ENV=development
CLIENT_URL=http://localhost:5173
ANTHROPIC_API_KEY=
```

Firebase Admin credentials come from Firebase Console → Project Settings → Service Accounts → Generate new private key.

**`client/.env`**

```env
VITE_API_URL=http://localhost:5000/api
VITE_FIREBASE_API_KEY=
VITE_FIREBASE_AUTH_DOMAIN=
VITE_FIREBASE_PROJECT_ID=
VITE_FIREBASE_APP_ID=
```

These come from Firebase Console → Project Settings → General → Your apps → SDK setup and configuration.

### 3. Run

```bash
# Terminal 1 — API on :5000
cd server && npm run dev

# Terminal 2 — SPA on :5173
cd client && npm run dev
```

Visit `http://localhost:5173`.

## API Overview

All endpoints are prefixed with `/api` and, except where noted, require a `Bearer <Firebase ID token>` header.

| Method | Endpoint | Description |
|---|---|---|
| GET | `/auth/me` | Get the current authenticated user |
| GET | `/pets/share/:token` | **Public.** Read-only pet profile by share token |
| GET | `/pets` | List the caller's pets |
| POST | `/pets` | Create a pet |
| GET | `/pets/:id` | Get one pet |
| PATCH | `/pets/:id` | Update a pet |
| DELETE | `/pets/:id` | Delete a pet |
| POST | `/pets/:id/symptom-check` | Run the AI symptom checker for a pet |
| GET / POST | `/pets/:id/records` | List / add health records for a pet |
| PATCH / DELETE | `/pets/:id/records/:rid` | Update / delete a health record |
| POST | `/pets/:id/reminders` | Create a reminder for a pet |
| GET | `/reminders` | List the caller's reminders |
| PATCH / DELETE | `/reminders/:rid` | Update / delete a reminder |
| GET | `/health` | Health check (used by hosting platforms) |

Responses follow a consistent envelope: `{ success: true, data }` on success, `{ success: false, message, errors? }` on failure.

## Deployment

Deploy `server/` as an Express web service (e.g. Render) and `client/` as a static Vite build (e.g. Vercel/Netlify), pointing `VITE_API_URL` at the deployed API and `CLIENT_URL` at the deployed frontend for CORS. See [server/docs/deployment.md](server/docs/deployment.md) for a detailed walkthrough.
